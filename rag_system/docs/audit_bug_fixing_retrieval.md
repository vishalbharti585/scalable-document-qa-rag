# Codebase Audit Report: Bug Fixing, Retrieval Optimization & Quality Improvement

**Project:** Scalable Document Question Answering System (RAG)  
**Date:** October 2026  
**Auditor:** Senior AI/ML & Full-Stack Engineer  

---

## 1. Executive Summary & Root Cause Analysis

Following a comprehensive audit of the backend ingestion, chunking, FAISS persistence, retrieval orchestration, prompt generation, and frontend rendering, the following confirmed issues were identified:

### Issue 1: Raw Markdown Syntax Display in Chat Interface
- **Affected File:** `frontend/chat.html` (lines 194–222)
- **Confirmed Root Cause:** The chat UI uses a primitive regex replacer in `renderMarkdown()` that only handles `#`, `##`, `###`, basic bold, and single-level bullet points. It completely ignores:
  - `####`, `#####`, `######` (subheadings generated by LLMs)
  - Tables (`| col1 | col2 |`)
  - Code blocks (`` ```python ... ``` ``) and inline code (`` `code` ``)
  - Ordered numbered lists (rendered as orphaned `<li>` without an `<ol>` container)
  - Blockquotes and horizontal dividers (`---`)
- **Fix:** Implement a comprehensive, modular Markdown parser in `frontend/js/markdown.js` supporting standard CommonMark/GFM syntax (H1–H6, tables, syntax-styled code blocks, nested lists, blockquotes) combined with strict XSS HTML entity sanitization.

### Issue 2: PDF Header/Footer Extraction Artifacts
- **Affected File:** `backend/app/services/ingestion/extractor.py` (lines 12–35)
- **Confirmed Root Cause:** PDF documents frequently repeat running headers (e.g. document titles, subject codes like `ELO-312`) and footers (e.g. page numbers) on every page. During ingestion, these repeated strings contaminate chunk embeddings, creating false lexical matches that degrade retrieval precision.
- **Fix:** Add a cross-page running header and footer detection filter that identifies identical lines appearing across multiple consecutive pages and strips them from the chunk text while strictly preserving page numbers in metadata.

### Issue 3: Similarity Score Interpretation & Calibration
- **Affected File:** `backend/app/services/vector_store/faiss_manager.py` (lines 198–220)
- **Confirmed Root Cause:** Vector search uses `faiss.IndexFlatIP` on $L_2$-normalized vectors, which computes exact Cosine Similarity $\in [-1.0, 1.0]$. However, hybrid lexical boosts were previously added without clear documentation or separate reporting, sometimes creating confusion between pure cosine similarity and hybrid relevance rank.
- **Fix:** Maintain and report both metrics clearly:
  - `raw_score`: Pure vector cosine similarity $\in [-1.0, 1.0]$.
  - `hybrid_score`: Calibrated relevance metric $\in [0.0, 1.0]$ incorporating token and exact-match boosts.
  - Document the exact mathematical formula in code and API responses.

### Issue 4: Source Excerpt Display & Card Readability
- **Affected File:** `frontend/chat.html` (lines 250–280)
- **Confirmed Root Cause:** Citation pills currently display a truncated single-line excerpt without the ability for users to expand or review the full supporting passage.
- **Fix:** Add an interactive expand/collapse toggle (`Show Excerpt` / `Hide Excerpt`) on each citation card with clean typography, page indicators, and relevance badges.

### Issue 5: Prompt Grounding & Partial Evidence Handling
- **Affected File:** `backend/app/services/retrieval/rag_service.py` (lines 8–25)
- **Confirmed Root Cause:** Previous prompts lacked explicit guidance on handling multipart questions where only a subset of questions can be answered from the document, sometimes leading to either complete refusal or partial extrapolation.
- **Fix:** Enhance the grounded system prompt with explicit multipart instructions, strict numerical/formula preservation, and conflict-resolution rules.

### Issue 6: Persistence & Multi-Tenant Restart Verification
- **Affected Files:** `backend/app/services/vector_store/faiss_manager.py`, `tests/`
- **Confirmed Root Cause:** While FAISS indexes are saved to atomic disk paths, automated unit tests lacked explicit restart-simulation verification (re-instantiating the manager and querying across process boundaries).
- **Fix:** Add automated tests specifically verifying index persistence after restart and multi-user isolation across all supported document types.
